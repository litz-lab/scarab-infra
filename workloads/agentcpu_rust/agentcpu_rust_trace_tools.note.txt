coderust_bat2393_tools was captured with one cargo build job (CARGO_BUILD_JOBS=1). At cargo's default parallelism the traced build fails under every DynamoRIO tried (10.0 in the image, the 11.3.0 release, and 11.90 built from the source Scarab reads traces with): the libgit2-sys build script, which compiles each C file in its own thread through posix_spawn (vfork), hangs with a vfork child stuck in a futex wait or dies with SIGSEGV, and rustc processes (console, idna) die with SIGSEGV. With one job the same build traces cleanly. Untraced, the instruction count of each rustc process (all threads) with one job is 0.997 to 1.005 times the count at default parallelism, 0.9996 over all 30 rustc processes of the test build; one job changes how rustc's code generation work is scheduled across its worker threads (jobserver tokens), not how much work there is. DynamoRIO 11.3.0 (SCARAB_TRACE_DR_HOME) was used for capture and conversion; it writes the trace format of the DR source Scarab reads with (trace version 6, offline file version 8).
